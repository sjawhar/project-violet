# Engine/Framework Research for Violet — AI-Agent-Optimized Development (Sept 2026)

## 1. Ranked Recommendation

**#1 Godot 4.5.x (Forward+/Vulkan, GDScript-primary, optional C# for tooling).** Godot is the only candidate that simultaneously satisfies all of Violet's hard requirements: a mature 2D toolset purpose-built for tilemap/character-controller platformers (`TileMapLayer`, `CharacterBody2D`, per-tile one-way collision, per-layer collision/nav/render toggles), a genuinely human-readable/diffable text scene+resource format (`.tscn`/`.tres`) that agents can read and hand-edit without a binary round-trip, first-class headless CLI (`--headless`, `--fixed-fps`, dedicated-server export) enabling deterministic automated playtesting and CI, an explosion of purpose-built MCP servers giving agents live scene-tree read/write and in-editor playtesting, an MIT license with zero revenue share, a native (if still-maturing) Wayland Linux editor that runs comfortably on the Radeon 890M's RADV Vulkan driver, and — critically — a real, documented 2026 precedent (the "Somnia" case study) of a team explicitly choosing GDScript+Godot over Rust/C++ *because* AI agents generate it reliably. Its two real weaknesses — no official console export, and LLMs sometimes confusing Godot 3 vs 4 APIs — are both mitigated (W4 Games middleware for consoles; MCP tools that ground agents in the live, current-version API instead of stale training data).

**Runner-up: TypeScript/Web stack (Phaser 4 or PixiJS 8 + Tiled).** If the flip condition below triggers, this is the fallback.

**Ranked order:** 1) Godot 4.5, 2) Web/TypeScript (Phaser 4 / PixiJS 8), 3) MonoGame, 4) Bevy, 5) GameMaker, 6) Defold, 7) Unity 6, 8) raylib, 9) LÖVE.

**Conditions that flip the pick:** (a) if a AAA-tier **console launch day-one** (not later via middleware) is a hard requirement → Unity 6 or MonoGame; (b) if the team decides code-only, zero-scene-editor workflow is actually *preferred* by the agent swarm (some evidence agents do better with pure text+API, no scene-tree state to desync) → the Web/TypeScript stack, which is even more text-native than Godot and trivially headless via Playwright/Node; (c) if Bevy's editor (MVP targeted per its public roadmap) and BSN text format mature and stabilize before Violet's production phase → Bevy becomes attractive for its ECS-native determinism and Rust's compile-time safety net for agent-written code.

## 4. Linux + AMD-iGPU Compatibility

The Radeon 890M (RDNA 3.5, 16 CU) is well within the performance envelope any of these 2D engines need — 2D pixel/vector rendering is trivial compared to the 3D benchmarks these GPUs are usually judged on. The relevant variable is **driver and editor maturity, not raw GPU power**. AMD folded its proprietary AMDVLK driver into RADV in May 2025, so RADV (Mesa) is now the single, actively-developed open-source Vulkan path on this laptop — mature, fast-iterating, and the reference path both Godot's Forward+ renderer and Bevy's wgpu-based renderer target. Godot's editor gained *native* Wayland support in 4.3 (Feb 2024) and continues to receive fixes (HDR/touch in 4.7, June 2026); it is not yet the default and can still have rough edges, but running with `--display-driver wayland` or falling back to XWayland both work today. Unity's Editor is officially Ubuntu-supported since 2015 but still runs its Linux Editor through XWayland with native Wayland marked experimental as of May 2026 — functionally fine on Pop!_OS 24.04, just not "native." GameMaker's Ubuntu IDE remains beta (Ubuntu 24 LTS only) with historically mixed reports on export reliability from Linux. Defold's Java-based editor has long had solid native Linux support. Bevy, MonoGame, raylib, and the web stack have no GUI editor at all, so "Linux editor quality" is really "does your text editor/IDE run on Linux" — trivially yes for all of them via VS Code, Zed, or any terminal-based agent harness.

## 5. Agent-Operability (CLI / API / MCP / text / headless)

**Godot** is the standout: `.tscn`/`.tres` are plain human-readable text (comparable to INI), GDScript files are plain text, the editor is fully scriptable via CLI (`--headless`, `--script`, `-s`), GUT gives JUnit-XML CI output, and a genuine MCP ecosystem (coding-solo/godot-mcp, Ziva AI, NPGameDev's toolkit) exposes 300+ tools for scene editing, screenshot capture, running the game, and reading debugger output — giving agents a live feedback loop instead of blind text generation. Deterministic playtesting is achievable via `--fixed-fps` + seeded RNG, though the physics engine itself isn't bit-exact-deterministic across platforms (acceptable for a puzzle-platformer, not for lockstep netcode).

**Unity** is agent-legible in a different way: huge C# training corpus, `-batchmode -nographics` headless CI, Unity Test Framework CLI, and a first-party "Unity AI" beta plus Unity-7-native Claude/Codex support (announced Dec 2026) — but scenes/prefabs are YAML with GUIDs and cross-references that are much harder for an agent to hand-edit or reason about diff-by-diff than Godot's format.

**Bevy** is maximally code-first (pure Rust, no binary scene state to desync) and has a community MCP debugger (`bevy_debugger_mcp`), but public reports (Hacker News, Reddit, 2026) already show agents struggling with Bevy-specific coordinate/ECS conventions due to thinner training data, and BSN's file-based `.bsn` loader doesn't exist yet — today you're editing Rust macros, not a portable scene asset.

**Web/TypeScript (Phaser 4, PixiJS 8, Excalibur)** is the most naturally agent-native format of all: everything is plain TS/JSON, npm has the deepest LLM familiarity of any ecosystem here, and headless/deterministic playtesting is a solved problem via Playwright driving headless Chromium with a fixed-timestep loop and seeded RNG — no engine-specific tooling required. The cost is weaker built-in platformer primitives (no CharacterBody-equivalent, must compose from Matter.js/Arcade Physics) and a much rockier console/Steam-native story.

**GameMaker, MonoGame, raylib, LÖVE, Defold** all offer text-based projects and CLI/automation to varying degrees (GameMaker's 2026 GM-CLI ships an *optional built-in Claude Code integration*), but none has anything like Godot's density of purpose-built MCP tooling as of Sept 2026.

## 6. Licensing, Commercial Rights, Steam AI-Disclosure

Godot (MIT), Bevy (MIT/Apache-2.0), Defold (Apache-2.0-derived), LÖVE (zlib), and raylib (zlib) impose **no revenue share and no royalty** — full commercial rights, no runtime fee risk ever. GameMaker is free for non-commercial use, $99.99 one-time for commercial desktop/mobile/web, $799.99/yr Enterprise only if targeting consoles — also zero royalty. Unity 6 is proprietary seat-based: free under $200k revenue/funding, then $2,200/seat/yr Pro (+5% Jan 2026) — no per-install runtime fee (cancelled Sept 2024) but a recurring subscription cost that scales with team size, not revenue. MonoGame is stewarded by a non-profit foundation (donation-funded), free and open. **Steam's AI-disclosure policy** (Jan 2024, clarified Jan 2026) is engine-agnostic: it requires disclosure only for generative-AI content that *ships in the game or is player-consumed* (art, audio, narrative, or fully-AI-authored code/assets), and explicitly exempts AI used as a development/workflow tool (code assistants, brainstorming) — so an agent-swarm-built Violet needs a disclosure only for whatever *shipped assets* (art, music, VO, procedurally-live-generated content) were AI-produced, regardless of engine. No candidate engine changes this calculus; Unity's built-in "Unity AI" beta and GameMaker's Claude Code integration are dev-tools and don't themselves trigger disclosure.

## 8. Risks / Unknowns

- **Godot console gap**: no first-party PS/Xbox/Switch export; W4 Games is a real, funded (Tencent-backed) solution but adds a commercial dependency and unpublished pricing — verify cost/terms before committing to a console SKU.
- **Godot C# web export is vaporware today** (May-2025 prototype, no ship date) — reinforces defaulting to GDScript, but blocks any plan that wanted C#-everywhere consistency.
- **GDScript-vs-C# LLM quality gap is vendor-sourced** ([INFERENCE]-adjacent: summerengine.com/ziva.sh are AI-tool vendors with an interest in flattering Godot) — corroborated independently by the Somnia case study and by Godot's documented text-format architecture, but treat exact "Claude Opus beats GPT at GDScript" rankings as directional, not authoritative.
- **Bevy's editor and BSN file format are both pre-1.0 and roadmap items**, not shipping products — real risk of building tooling atop foundations that still change every ~3-month release train.
- **Unity Editor Wayland support is experimental** — should be fine via XWayland on Pop!_OS 24.04, but not verified on this exact Radeon 890M/Mesa combination; recommend a smoke test before any Unity commitment.
- **Unity 6 pricing figures cited here are from Sept 2024 (>12 months old)** — flagged stale; re-check unity.com/products/pricing-updates before finalizing budget, since another price change is already scheduled for Jan 2026 and the situation has moved fast historically.
- **No public, fully-autonomous "built end-to-end by AI agents with zero human code" game exists in any engine as of Sept 2026** — every 2025-2026 example found (Somnia, Unity "Hedgietown," GameMaker Claude Code demos) is agent-*assisted* or human-orchestrated multi-agent, not agent-*autonomous*. Plan for a human-in-the-loop orchestration model (like Somnia's PM/Architect/Lead-Dev/QA/Security/DevOps roles), not a "prompt-to-shipped-game" pipeline.
- **Determinism is "good enough," not bit-exact**, in every non-lockstep-netcode-focused engine here (Godot, Unity, Bevy) due to floating-point physics — fine for a single-player puzzle-platformer's automated playtesting, but would need engine-specific hardening (integer math, deterministic physics plugin) if Violet ever adds competitive/replay features.
